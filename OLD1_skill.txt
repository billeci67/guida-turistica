# Guida turistica di una giornata — REGOLE ASSOLUTE

Produce una guida HTML autonoma, nello stile approvato (Rotterdam/Amsterdam): in apertura la mappa Google Maps dell'intero percorso (schede A piedi, Mezzi pubblici, Auto), poi mappa schematica, riepilogo con orari e distanze, tappe con foto, descrizioni estese, "Cosa fotografare", "Come proseguire", pranzo, rientro e consigli.

La pagina NON si scrive a mano: si compila un file JSON e lo script lo trasforma in HTML.

---

## ⛔ REGOLE CHE NON AMMETTONO ECCEZIONI

### 1. IL FILE HTML DEVE ESSERE CREATO DAVVERO
- Ogni richiesta di guida si chiude SEMPRE con uno o più file HTML reali in `/mnt/user-data/outputs/` (es. `milano-guida-giorno-1.html`).
- Presenta i file con `present_files`.
- VIETATO consegnare la guida solo come testo in chat, artifact, PDF, Markdown o anteprima.
- VIETATO fermarsi alla sola proposta quando l'utente ha chiesto di creare subito.
- Se manca uno strumento (foto, ricerca luoghi, web), il file si crea COMUNQUE: foto assenti con `photo_note`, informazioni non verificate dichiarate come tali.
- La risposta NON è completa finché il file non è stato generato con lo script e presentato.

### 2. IL PERCORSO GOOGLE MAPS DEVE ESSERE GENERATO CON LO SCRIPT
- Per ogni guida si crea SEMPRE il percorso completo su Google Maps (prima → ultima tappa + rientro) nelle tre modalità: a piedi, mezzi pubblici, auto.
- Si ottiene ESCLUSIVAMENTE con:
  ```bash
  python scripts/build_guide.py --links <json>
  ```
- VIETATO scrivere i link a mano.
- VIETATO sostituire il percorso completo con link a singole tappe o con la sola mappa schematica.
- Una guida senza la sezione "Il percorso su Google Maps" con tutte e tre le modalità NON è consegnabile: va rigenerata.

### 3. FOTO — QUESTA È LA REGOLA PIÙ IMPORTANTE DI TUTTE
- Per OGNI SINGOLA tappa SEI OBBLIGATO a ottenere coordinate e foto dai tool Places.
- Flusso obbligatorio:
  1. `places_search` (una o più query) → ottieni `place_id`, `lat`, `lon`, `cid`
  2. `places_map_display_v0` con TUTTI i `place_id` insieme → ottieni gli URL delle foto
  3. Copia 2 URL foto per tappa ESATTAMENTE come restituiti dal tool (non inventarli, non modificarli)
- Se una tappa non restituisce foto → `photos: []` e `photo_note: "Nessuna immagine disponibile qui"`.
- VIETATO inventare URL di foto.
- VIETATO saltare `places_map_display_v0` perché "tanto poi si vede" o perché "è più veloce".
- VIETATO lasciare tutte le tappe senza foto senza aver prima chiamato i tool.
- Una guida in cui TUTTE le tappe hanno `photo_note` senza aver tentato i tool Places è CONSIDERATA NON VALIDA: rifalla.

### 4. NON INVENTARE DATI
- Orari, prezzi, chiusure: verifica sul web o dichiara esplicitamente "non verificato".
- Coordinate: solo da `places_search` o fonti ufficiali.
- Testi: fatti verificabili, non fantasie.

Città, tappe preferite (facoltative), data, orari (default 10:00–18:00), partenza/arrivo (default stazione centrale), mezzi, vincoli di spesa, temi.
Più città = un file HTML per ogni città.

### 2. Verifica gli strumenti

### 3. Proposta (solo se l'utente NON ha chiesto di creare subito)
1. Cerca tappe adatte sul web (fonti ufficiali).
2. Controlla orari/prezzi/chiusure per la data.
3. Ordina le tappe in modo geografico e realistico.
4. **OBBLIGATORIO**: ricava coordinate con `places_search`, scrivi JSON provvisorio, esegui:
   ```bash
   python scripts/build_guide.py --links provvisorio.json
   ```

6. NON scrivere ancora la guida completa.

### 4. Dati e foto (dopo conferma OPPURE subito se richiesto)
1. Coordinate e `cid` da `places_search` (riusali se già fatti).
2. **OBBLIGATORIO**: chiama `places_map_display_v0` UNA VOLTA con tutti i `place_id`.
3. Prendi 2 foto per tappa. Se mancano → `photo_note`.
4. Mai foto di persone. Luoghi sensibili: niente foto, nome "(opzionale)".

### 5. Scrivi il JSON
Segui `references/schema.md`.
- Italiano, tono concreto, 2–3 paragrafi per tappa (~120–170 parole).
- Solo fatti verificati o dichiarati come non verificati.
- "Cosa fotografare" e "Come proseguire" obbligatori per ogni tappa.
- `along` solo per tratti lunghi interessanti.

### 6. Genera e controlla (OBBLIGATORIO)
```bash
python scripts/build_guide.py dati.json /mnt/user-data/outputs/<citta>-guida.html
```
- Correggi TUTTI gli errori.
- Controlla gli avvisi (distanze, etichette mappa, parti Google Maps).
- Verifica che l'HTML contenga la sezione "Il percorso su Google Maps".
- Se manca o è incompleta → correggi e rigenera.
- Presenta il file con `present_files`. Questo passo è OBBLIGATORIO.

### 7. Risposta finale (breve)
- Link Google Maps a piedi e auto + primo spostamento mezzi pubblici.
- Cosa è stato verificato e cosa no.
- Dove sta il file.
- Ricorda che foto e mappe si caricano da internet.

# Schema del JSON della guida

Esempio: `assets/esempio-rotterdam.json`. Testi in italiano semplice; `**così**` produce grassetto. Non usare HTML.

## Livello principale

| Campo | Obbligatorio | Descrizione |
|---|---|---|
| `lang` | no | "it" di default |
| `title` | sì | Titolo della scheda del browser |
| `h1` | sì | Titolo grande della guida |
| `intro` | sì | 2 frasi: cosa si vede, partenza e arrivo, data |
| `facts` | no | Lista di `{"v":"10","l":"tappe"}` |
| `transit_label` | no | Nome dei mezzi pubblici ("metro", "tram", "mezzi") |
| `return_leg_label` | no | Etichetta del rientro sulla mappa schematica |
| `return_leg` | no | `false` se non si rientra al punto di partenza |
| `map` | no | `{"note": "...", "water": {...}}` |
| `google` | no | Mappa Google Maps dell'intero percorso: `modes`, `default_mode`, `route_ids`, `mode_notes`, `general_note`, `note`, `buttons` |
| `lunch` | no | `{"title","intro","items":[{"t","d"}]}` |
| `return` | no | `{"title","lead","items":[...]}` |
| `tips` | no | Lista di consigli pratici |
| `summary_note`, `photo_credit`, `footer`, `map_aria` | no | Testi opzionali |
| `stops` | sì | Lista delle tappe, nell'ordine di visita |

### Mappa Google Maps (`google`)
La pagina si apre con "Il percorso su Google Maps": schede A piedi / Mezzi pubblici / Auto.
Nessun campo obbligatorio: senza `google` la sezione si genera dalle tappe.

| Campo | Descrizione |
|---|---|
| `modes` | `walking`, `transit`, `driving` (default: tutte) |
| `default_mode` | Scheda aperta all'inizio |
| `route_ids` | Id tappe incluse (default: tutte) |
| `mode_notes` | Note per modalità |
| `general_note` | Nota sotto le schede |
| `note` | Testo sopra i pulsanti del percorso guida |
| `buttons` | Pulsanti percorso a piedi + mezzi |

Limiti Google Maps: a piedi/auto max 11 punti per link; mezzi pubblici una coppia per volta.
`python scripts/build_guide.py --links dati.json` stampa tutti i link.

## Tappa (`stops[]`)

| Campo | Obbl. | Descrizione |
|---|---|---|
| `id` | sì | Slug unico |
| `name` | sì | Nome mostrato |
| `time` | sì | Arrivo `HH:MM`, ordine crescente |
| `dist` | sì | Dalla precedente, es. `"0,8 km, 10 min"` o `"metro 25 min + 1 km a piedi"`; prima tappa `"partenza"` |
| `lat`, `lon` | sì | Coordinate decimali |
| `cid` o `url` | sì | `cid` Google Maps oppure `url` completo |
| `hours` | sì | Orari per la data; segnala se chiuso |
| `price` | sì | Ingresso e costi |
| `photos` | no* | Lista di URL `https://` (di solito 2). *Se vuota serve `photo_note` |
| `photo_note` | no* | Obbligatoria se `photos` è vuoto |
| `text` | sì | 2–3 paragrafi |
| `shoot` | sì | Cosa fotografare |
| `next` | sì | Come proseguire |
| `along` | no | `{"zone": "...", "foto": ["...", "..."]}` |
| `leg` | no | `"transit"` se il tratto in arrivo è in metro/tram |
| `label_pos` | no | `right` (default), `left`, `above`, `below` |

## Controlli dello script
- **Errori** (guida non generata): campi mancanti, id duplicati, orari non crescenti, URL foto non `https://`, pulsanti con id sconosciuti, più di 9 tappe intermedie.
- **Avvisi**: tappe senza foto né `photo_note`, descrizioni troppo brevi, distanze incoerenti, etichette mappa sovrapposte, percorso Google diviso in più parti.
